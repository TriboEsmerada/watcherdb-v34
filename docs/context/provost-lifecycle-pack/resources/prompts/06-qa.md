# Etapa 06 — QA de {{PROGRAM_NAME}}

Monta a pirâmide de qualidade em níveis — cada nível apanha o que o
anterior não vê. Testes correm com mocks/fixtures; PROIBIDO tocar em
dados ou serviços reais a partir de testes.

## Níveis

1. **Unitários** — lógica de domínio pura; rápidos, sem I/O.
2. **Contratos de API** — cada endpoint: schema de resposta, códigos
   de erro, auth exigida. Um endpoint sem teste de contrato é um
   contrato verbal.
3. **Integração mockada** — camada de dados com fixtures; inclui os
   casos de degradação (fonte indisponível → resposta degradada, não
   500).
4. **Smoke real** — a app arranca? /healthz responde? primeira página
   carrega? Corre após CADA build/deploy, não só em release.
5. **UI no alvo real** — teste manual/automatizado no BROWSER e nos
   viewports 360/768/1366 (bloco XPLAT). Event handlers inline e
   quoting JS são a causa nº1 de "funciona no code review, morre no
   click" — testar o click, não o código.
   <!-- EXPAND: se {{TARGET_PLATFORMS}} inclui android/ios, acrescenta
   passo de teste em device/emulador real por release e nomeia a
   ferramenta recomendada para o framework escolhido na etapa 02. -->
6. **Adversarial** — inputs maliciosos/absurdos: strings gigantes,
   apóstrofes, unicode, SQL metacaracteres, datas impossíveis,
   concorrência (duas escritas simultâneas).

## Regras de triagem
- Teste flaky é bug de teste: corrige ou remove, nunca "re-corre até
  passar".
- Falha classificada antes de corrigida: bug de produto / bug de
  teste / mudança de contrato — cada uma tem tratamento diferente.
- Bug encontrado em produção → primeiro o teste que o teria apanhado,
  depois o fix.

## Critério de saída
- [ ] Pirâmide níveis 1-4 a correr em comando único (make/task/script)
- [ ] Nível 5 feito nos 3 viewports antes de qualquer "shipped"
- [ ] Suite verde no branch antes de merge (gate, não sugestão)
